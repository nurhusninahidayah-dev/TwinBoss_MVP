# TwinBoss

TwinBoss is a React + Vite demo for handling SME refund exceptions with a human in the loop. It simulates a three-tier Customer → Staff → Owner Maker-Checker workflow using synthetic order data and local React state. When configured, Groq provides evidence analysis and a business recommendation; WhatsApp drafts are generated from local templates.

## Run locally

1. Install Node.js 20 or newer.
2. Install dependencies:

   ```bash
   npm install
   ```

3. For AI features, copy `.env.example` to `.env` and add a Groq API key from the free tier:

   ```env
   VITE_GROQ_API_KEY=your_groq_api_key
   ```

4. Start the app:

   ```bash
   npm run dev
   ```

Without a key, the dashboard and Staff/Boss handoff still work; AI actions show a setup message. Restart the dev server after changing `.env`.

## Three-tier Maker-Checker workflow

1. **Customer (maker):** Submit an order ID, issue description, optional damage photo, and bank destination.
2. **Staff (checker):** Review the evidence and order record, then verify eligible requests for the owner.
3. **Owner (checker):** Review the business recommendation and reasoning, then approve cash, offer store credit, or reject. The owner can make the final decision without an override modal.
4. **Staff (execution):** Process an approved refund or store credit, or prepare a customer notice for a rejected request. Share the locally generated message draft through WhatsApp if desired.
5. **Auto-Pilot:** When enabled, automatically applies the business constitution to staff-verified requests under RM100 with at least 70% validity and low risk. Regular customers such as Ali receive store credit for orders over RM50; VIP customers receive cash approval unless a rejection rule applies.

Groq evidence analysis and business recommendations use the Chat Completions API with `openai/gpt-oss-20b`, as configured in `src/App.tsx`. WhatsApp messages are not generated by AI: the app fills local message templates using the request, decision, and order details.

## Workspace boundaries

- Customer profiles are local preview data; submitted requests and the wallet exist only in React memory and reset on refresh.
- The Orbyte Hub and CRM labels are visual integration previews. No Orbyte API or activity log is connected.
- The payment dialog creates a local transaction reference only. No bank transfer, WhatsApp message, or receipt is sent.
- Role selection is a workflow preview, not authentication or secure access control.
- The optional photo is checked for attachment only; its contents are not uploaded or sent to Groq.
- `VITE_GROQ_API_KEY` is bundled into browser code and visible to app users. Use only a disposable, rate-limited demo key; never use this client-side setup for a production secret.
- Only Groq is contacted, and only when an AI action is requested. The rest of the app runs locally.

## Commands

- `npm run dev` — start Vite's local development server.
- `npm run typecheck` — check the TypeScript app.
- `npm run build` — typecheck and create a production build in `dist/`.
- `npm run preview` — preview the production build locally.
